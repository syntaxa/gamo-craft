# Архитектура игры (MVP) + декомпозиция задач + план реализации

## 1. Цели архитектуры
Архитектура должна обеспечить:
- Быстрый запуск MVP в браузере.
- Удобную поддержку мыши и сенсорного ввода (Android-планшеты).
- Ясное разделение между обучением и развлекательной частью.
- Простое добавление новых учебных программ после математики.
- Надежное сохранение прогресса ребенка между сессиями.

## 2. Архитектурные принципы
- **Offline-first для MVP**: игра полностью работает локально в браузере без обязательного сервера.
- **Модульность домена**: отдельные модули для обучения, экономики, инвентаря, строительства, наград.
- **Single Source of Truth**: единое состояние профиля игрока и прогресса.
- **Event-driven взаимодействия**: ключевые действия публикуют события (например, `lesson.completed`, `egg.opened`).
- **Детский UX-by-default**: крупные кнопки, минимум сложных экранов, короткие циклы действий.

## 3. Технологический стек (предложение для MVP)
- **Frontend framework**: React + TypeScript.
- **Сборка**: Vite.
- **Состояние**: Zustand (или Redux Toolkit, если потребуется строгая схема событий).
- **Рендер игрового мира**: WebGL через Three.js + React Three Fiber (R3F).
- **UI**: обычные React-компоненты + CSS variables для тем.
- **Хранилище**: IndexedDB (через Dexie) + fallback на LocalStorage для критичных снимков состояния.
- **Тесты**:
  - Unit: Vitest.
  - Компоненты: Testing Library.
  - E2E: Playwright (desktop + tablet viewport).

Почему так:
- Быстрая разработка веб-прототипа.
- Хорошая поддержка pointer-событий и адаптивного UX.
- Поддержка 3D-сцены и камеры от первого лица в браузере.

## 4. Контекстная схема системы
Подсистемы MVP:
1. **App Shell**
- Навигация между экранами: Мир, Учеба, Магазин, Яйца, Профиль.
- Инициализация состояния игрока.

2. **Learning Module**
- Генерация заданий (сложение/вычитание до 20).
- Генерация уровня `Математика - бронзовый`: сложение до 40, доступно сразу.
- Генерация уровня `Математика - серебряный`: умножение и деление до 20, доступно сразу.
- Генерация уровня `Учим слова - Легендарно`: задания `letter_gap` (слово с пропущенной буквой, 6 вариантов), доступно сразу.
- Проверка ответов и подсказки.
- Подсчет результатов урока.

3. **Reward & Economy Module**
- Начисление кото-монеток за ответы и бонусы.
- Проверка баланса и списание при покупках.

4. **Inventory & Catalog Module**
- Каталоги: ресурсы, яйца, косметика.
- Инвентарь игрока: количество ресурсов, коллекция наград.
- Minecraft-style инвентарь: full inventory grid + hotbar на единых данных, операции pickup/place/drag-and-drop/swap/merge/split/delete для стеков и видимый carried-stack feedback под курсором при переносе.
- Placeable poster items как обычные предметы инвентаря.

5. **Egg Loot Module**
- Покупка яйца.
- Ролл награды по таблице вероятностей.
- Выдача предметов, применимых в FPV-строительстве в MVP.
- Новый тип дорогого яйца `egg_meme` (`Котовое яйцо`) за 200 котокоинов с poster-наградами категории `cats`.
- Новый тип дорогого яйца `egg_sbear` (`Яйцо Super bear`) за 400 котокоинов с poster-наградами категории `sbearadventure`.
- Обработка дубликатов (конвертация в кото-монетки).

6. **Build World Module**
- 3D мир на воксельной сетке.
- Поставить/удалить блок.
- Разместить/удалить placeable-плакаты на вертикальных поверхностях.
- Камера и управление от первого лица (FPV).
- Вертикальная физика: одинарный прыжок, непрерывное падение под действием гравитации и разрешение столкновений как с верхними, так и с нижними гранями твердых блоков.
- Расход ресурсов при строительстве.

7. **Persistence Module**
- Сохранение/загрузка профиля, мира, инвентаря, статистики обучения.

8. **Input Abstraction Module**
- Единый слой ввода для mouse/touch/pen через Pointer Events.
- Нормализация жестов (tap/drag/long-press).
- Маппинг jump: `Space` на desktop и отдельный touch-control на coarse-pointer устройствах.

## 6. Логическая архитектура по слоям
1. **Presentation Layer**
- React-экраны и компоненты.
- Рендер мира + HUD.

2. **Application Layer (Use Cases)**
- `completeLesson()`, `grantLessonReward()`, `buyEgg()`, `openEgg()`, `placeBlock()`.
- Оркестрация сценариев между доменными сервисами.

Целевой Application Layer описан как направление развития, но активная реализация пока проще: React-экраны вызывают доменные сервисы и Zustand-store напрямую. `src/application/useCases/*.ts` и `src/features/*/use*Controller.ts` остаются scaffold и не считаются текущим runtime-контрактом. Фактическая оркестрация сценариев:
- уроки: `LessonScreen` + `learning/service` + `useAppStore.addCatCoins`;
- магазин: `ShopScreen` + `useAppStore.spendCatCoins/addInventoryItem`;
- яйца: `EggsScreen` + локальный roll + `useAppStore.addBlockRewardItem`;
- строительство: `BuildScreen` + `useAppStore.placeVoxel/removeVoxel`.

Если проект вернется к отдельному Application Layer, перенос должен быть выполнен как явный рефакторинг без изменения продуктового поведения.

3. **Domain Layer**
- Правила математики, экономики, лута, строительства.
- Валидация и инварианты.

4. **Infrastructure Layer**
- Репозитории для IndexedDB.
- Таблицы каталогов из JSON-конфигов.

## 7. Ключевые инварианты (обязательные правила)
- Баланс кото-монеток не может быть отрицательным.
- Нельзя поставить блок, если нет ресурса в инвентаре.
- Нельзя разместить плакат, если предмета нет в инвентаре.
- Плакат размещается только на вертикальной поверхности, занимает `2x2` блока, требует один валидный опорный face и не может перекрывать другой плакат, decor occupancy или твердые блоки мира.
- При активном poster item Build HUD показывает `2x2` wireframe preview валидного/невалидного размещения.
- В мире плакат отображается как тонкая основа с изображением на лицевой стороне, чтобы прозрачные области картинки не просвечивали текстурой блока-опоры.
- Прыжок разрешен только из grounded-состояния; двойной прыжок и прыжок в воздухе запрещены.
- Падение игрока выполняется непрерывным физическим движением, без телепортации на нижнюю поверхность.
- После bootstrap без сохранений и после reset игрок получает только `24` кирпича (`block_brick_red`) в `inventory.resources` и `inventory.blocks`.
- Ответ урока начисляет награду только один раз за сессию.
- Сложность математики не повышается при низкой точности.
- Любой лут из яйца должен иметь запись в каталоге предметов.
- Любой visual reward из яйца отображается через общий паттерн витрины (`shop-lot`) и автоматически скрывается после fade-out.

## 8. Пользовательские потоки (MVP)
## 8.1. Обучение -> Награда -> Строительство
1. Игрок открывает экран «Учеба».
2. Запускает мини-урок; при каждом новом старте генерируется новый набор задач (5-10 задач).
3. Получает кото-монетки.
4. Переходит в «Мир» и строит, тратя ресурсы.
5. При нехватке ресурсов покупает набор в магазине.

## 8.2. Яйца и случайные награды
1. Игрок открывает «Яйца».
2. Покупает яйцо за кото-монетки.
3. Запускается анимация.
4. Выпадает награда из таблицы.
5. Награда сразу попадает в инвентарь блоков и доступна в FPV-строительстве.
6. При дубликате предмета выдаются кото-монетки-компенсация.

Для `Котового яйца`:
1. Игрок покупает `egg_meme` за 200 котокоинов.
2. Выпадает poster item с локальной meme cat картинкой категории `cats` из curated-набора.
3. Плакат попадает в Minecraft-style inventory и поддерживает обычные операции со стаками.
4. В Build-режиме плакат можно выбрать в hotbar и разместить на вертикальной поверхности с `2x2` wireframe preview.

Для `Яйца Super bear`:
1. Игрок покупает `egg_sbear` за 400 котокоинов.
2. Выпадает poster item с локальной картинкой категории `sbearadventure` из curated-набора.
3. Плакат попадает в Minecraft-style inventory и поддерживает обычные операции со стаками.
4. В Build-режиме плакат можно выбрать в hotbar и разместить на вертикальной поверхности с `2x2` wireframe preview.

## 9. Адаптация под мышь и touch
- Основа: Pointer Events вместо раздельной логики mouse/touch.
- Взаимодействия:
  - desktop: `WASD` для движения + `Space` для одинарного прыжка + мышь для обзора;
  - tablet: виртуальный джойстик движения + отдельная кнопка прыжка + свайп для обзора камерой;
  - при потере фокуса окна/вкладки мир автоматически ставится на паузу, а состояние зажатых клавиш сбрасывается;
  - tap/click: поставить блок в точку под курсором/касанием;
  - удержание ПКМ: свободный обзор камеры (free camera view).
  - ЛКМ выполняет действие активного слота hotbar.
  - прыжок срабатывает только при опоре на твердую поверхность.
- UI-правила:
  - Минимальная целевая зона: 44x44 px.
  - Крупные экранные кнопки действий для touch-режима.
  - Hotbar в стиле Minecraft: слот 1 фиксирован под ластик (удаление), слоты 2-9 под ресурсы.
  - По умолчанию активируется слот с первым ресурсом (обычно слот 2); если ресурсов нет, активен пустой слот 2 и ЛКМ не выполняет действие.
  - При удалении блока ластиком ресурс возвращается в соответствующий слот инвентаря.
  - Full inventory использует Minecraft-style baseline: main grid, hotbar row, stack counts, selected/hover states, drag-and-drop для переноса целых стеков, pickup/place/swap/merge/split/delete и видимый carried-stack feedback под курсором.
  - Превью позиции установки показывается тонкой рамкой только по ребрам блока (без диагоналей).
  - Рамка учитывает \"прилипание\" к грани блока: показывает точную клетку, где появится новый блок.
  - Для активного плаката превью показывает область `2x2` на вертикальной поверхности и запрещает перекрытие существующих плакатов.

## 10. Нефункциональные требования (MVP)
- Время загрузки первого экрана: до 3 сек на среднем планшете.
- FPS в режиме строительства: целевой 30+ на Android-планшете среднего уровня.
- Стабильность сохранения: не терять прогресс при перезапуске вкладки.
- Локализация: русский язык как базовый.

## 11. Риски и меры
1. Слишком сложный рендер «как Minecraft».
- Мера: в MVP использовать упрощенную low-poly/voxel графику, ограниченный размер мира и легкие материалы.

2. Потеря сохранений в браузере.
- Мера: IndexedDB + периодический автосейв + синхронный LocalStorage-снимок после каждого изменения мира + версионирование схемы.

3. Дисбаланс экономики (слишком легко/сложно копить валюту).
- Мера: конфигурируемые коэффициенты наград и цен, A/B тест вручную.

4. Слабая удерживаемость.
- Мера: короткие циклы наград и коллекционирования, ежедневная цель.

## 15. Definition of Done для MVP
MVP считается готовым, если:
1. Ребенок может пройти мини-урок по математике до 20.
2. За урок начисляются кото-монетки (монетки с головой кота).
3. Кото-монетки можно потратить на ресурсы и яйца.
4. Яйца выдают случайные награды, которые применимы в FPV-строительстве.
   - В том числе `Котовое яйцо` выдает placeable-плакаты с локальными meme cat изображениями категории `cats`, а `Яйцо Super bear` — placeable-плакаты категории `sbearadventure`.
5. В мире можно строить из купленных ресурсов и наград из яиц.
   - Плакаты размещаются на вертикальных поверхностях как `2x2` предметы с wireframe-подсказкой.
6. В MVP доступен 3D-режим строительства с видом от первого лица.
   - Перемещение включает одинарный прыжок и плавное падение без телепортации.
7. Игра работает на desktop (мышь+клавиатура) и Android-планшете (touch).
8. Прогресс стабильно сохраняется и восстанавливается.

## 16. Модуль ресурс-паков (MVP+)
- Добавляется `Resource Pack Layer`: реестр паков + активный pack id в глобальном store.
- Рендер мира и HUD получают ассеты через pack-резолвер вместо жестко заданных цветов.
- Минимальный контракт MVP:
  - `world`: texture для земли, sky texture, материал-спеки по `blockId`.
  - `ui`: texture для фона, карточек, кнопок, HUD-панелей и hotbar.
- Resource Pack Layer поддерживает прозрачные материалы блоков через параметры `transparent` и `opacity`.
- `cartoon-blocky-v1` содержит ассеты `world/block_coin.png` и `world/block_glass.svg`.
- Визуальный ассет `block_glass` включает тонкую темно-серую рамку по ребрам, чтобы полупрозрачный блок был заметен в мире.
- UI магазина использует ту же ориентацию текстур граней блока, что и Build-рендер; для `res_planks` боковые грани повернуты на 90°.
- По умолчанию активируется `cartoon-blocky-v1`; дальнейшие паки должны подключаться без изменения use-case логики.


## 17. Твердые блоки и стартовая поверхность
- Стартовая поверхность генерируется доменным world-сервисом как слой вокселей `block_grass_dirt` на уровне `y=0`.
- Коллизии игрока рассчитываются в Build-модуле по пересечению объема игрока и AABB воксельных блоков.
- Инвариант: перемещение игрока не должно приводить к попаданию внутрь твердого блока.
- Вертикальная физика должна останавливать подъем при ударе о нижнюю грань подвешенного блока и удерживать игрока на верхней грани при приземлении.
- Верхняя граница постановки блоков: `y < 24`.

## 18. Политика отображения touch-элементов
- Визуальный джойстик и иные touch-only контролы отображаются только для устройств с coarse pointer.
- На desktop эти элементы скрываются, чтобы не засорять игровой экран.

## 19. Подход к наполнению орфографического словаря
- Цель словаря: обеспечить генерацию детских орфографических заданий с контролируемой сложностью и предсказуемым качеством.
- Базовая механика задания в MVP для орфографии: выбор правильного написания из `3` вариантов (`1` верный + `2` ошибочных).
- Источники данных:
  - базовый морфологический корпус (например, OpenCorpora) как источник лемм и словоформ;
  - частотный словарь русского языка как фильтр по понятности и бытовой употребимости;
  - ручной `whitelist` учебной команды для возрастной валидации контента 6-9 лет.
- Pipeline наполнения:
  - импорт лемм и форм;
  - отбор по частотности, длине слова и базовым эвристикам "детского" словаря;
  - авторазметка по орфографическим правилам (`ruleTags`);
  - ручная модерация спорных слов и исключений;
  - экспорт в версионированный контент-файл `src/content/learning/orthography-1.v1.json`.
- Структура записи словаря:
  - `id`, `lemma`, `correct`, `forms[]`, `ruleTags[]`, `difficulty(A/B/C)`, `frequencyBand`, `allowedForAge`.
- Генерация неверных вариантов (дистракторов):
  - часть хранится как вручную подтвержденные пары ошибок;
  - часть генерируется правилами замен (например, типовые школьные ошибки);
  - для каждой задачи инвариант: ровно один корректный ответ и уникальные варианты.
- Фильтр качества distractor-вариантов:
  - приоритет у ошибок, генерируемых целевым `ruleId`; кросс-правила разрешены только из ограниченной цепочки, заданной для этого `ruleId`;
  - исключаются варианты, которые совпадают с корректными словами словаря (`lexicon.correct`);
  - исключаются варианты, не проходящие проверку правдоподобия орфограммы (pattern-based `rule plausibility`);
  - генератор не использует «свободные» шумовые подстановки вне орфографических правил.
- Базовый набор орфограмм для 7-9 лет:
  - `жи/ши`, `ча/ща`, `чу/щу`;
  - безударные гласные в корне;
  - парные согласные;
  - непроизносимые согласные;
  - разделительные `ь` и `ъ`;
  - удвоенные согласные (частотные слова).
- Качество и инварианты:
  - запрет редких, жаргонных и возрастно-неподходящих слов;
  - запрет дубликатов `id` и конфликтующих `ruleTags`;
  - проверка, что каждое слово связано минимум с одним учебным правилом.
- Версионирование и поддержка:
  - словарь ведется как контент-каталог с явной версией (`v1`, `v2`, ...);
  - изменение словаря не требует изменения доменных use-case API, пока сохраняется контракт полей.
- Лицензии:
  - для каждого внешнего источника фиксируются условия использования и атрибуция в документации проекта;
  - в релиз допускаются только источники, совместимые с коммерческим использованием.
