# Команда проекта «обнови постеры»

## Цель
Закрепить в правилах проекта короткую пользовательскую команду `обнови постеры`, которая запускает полный повторяемый workflow пополнения набора meme-постеров без необходимости каждый раз перечислять шаги вручную.

## Триггер
Когда пользователь пишет точную команду `обнови постеры`, агент должен трактовать её как запрос на импорт всех исходных изображений из `public/assets/posters/toadd`.

## Обязательный workflow
После получения команды агент должен:
1. Проверить содержимое `public/assets/posters/toadd`.
2. Подготовить новые runtime-изображения постеров по уже действующему контракту проекта и сохранить их в `public/assets/posters/transparent`.
3. Добавить новые poster items в `src/content/catalogs/items.posters.v1.json`.
4. Добавить соответствующие записи в таблицу `loot_meme_posters` файла `src/content/catalogs/lootTables.v1.json`.
5. Удалить исходные изображения из `public/assets/posters/toadd` только после успешного добавления runtime-ассетов и обновления каталогов.
6. Проверить, нужны ли сопутствующие изменения документации проекта; если да, внести их без changelog-блоков.

## Границы поведения
- Команда применяется только к папке `public/assets/posters/toadd`.
- Если папка отсутствует или пуста, агент должен явно сообщить, что импортировать нечего, и не менять каталоги.
- Агент не должен удалять исходные изображения до завершения всех необходимых изменений.
- Агент должен следовать существующему контракту проекта для poster items: локальные runtime-изображения, каталог `items.posters.v1.json`, loot table `loot_meme_posters`.

## Изменения в репозитории
- Добавить правило команды в `AGENTS.md`.
- Уточнить техническую документацию так, чтобы staging-папка `public/assets/posters/toadd` и удаление исходников после успешного импорта были описаны явно и не противоречили текущему poster workflow.

## Проверка
- Убедиться, что правило в `AGENTS.md` однозначно описывает триггер и ожидаемое поведение.
- Убедиться, что техническая документация согласована с правилом.
- Не менять продуктовые требования, так как команда описывает рабочий процесс агента, а не поведение игры.
